# SROT

Low-cost water network monitoring on ESP32. A monitor sits on a pipe and measures pressure and flow (and, depending on the build, water quality or tank level). An Android app connects to it over Wi-Fi and shows the readings and any alerts in plain language. Two monitors on the same pipe can estimate where a burst happened from the arrival times of the pressure wave.

It is aimed at Indian municipal supply: intermittent schedules, plastic pipe, small budgets. A basic monitor is about ₹2,200 in parts.

## Status

| Part | State |
|---|---|

| [docs/](docs) | Design documents for the whole system. |
| backend | Not started. The docs describe it (MQTT, TimescaleDB, WNTR), but nothing is implemented yet. |

The design documents cover more than what is built. The accuracy numbers in them (burst location within a metre, for example) are design targets from the physics, not results measured on real hardware.

## Try it without hardware

You need a current Node.js LTS and an Android phone with [Expo Go](https://expo.dev/go).

```bash
cd mobile
npm install
```

On Windows, `run-demo.bat` then starts the emulator and the Expo server together. On other systems, run these in two terminals:

```bash
node devsim/device-emulator.mjs
```

```bash
cd mobile && npx expo start --lan
```

Scan the QR code with Expo Go. In the app, go to **Add → Demo monitors on a PC** and enter the address the emulator prints. The phone and the PC need to be on the same Wi-Fi. A simulated burst happens about every two minutes.

More detail, including the Windows firewall step: [docs/ANDROID-GUIDE.md](docs/ANDROID-GUIDE.md).

## Run it on hardware

1. Build the board from the [parts list](hardware/SHOPPING-LIST.md). The cheapest useful setup is the [starter kit](hardware/STARTER-KIT.md): two flow sensors on an ESP32, about ₹1,350.
2. Flash the firmware. See [firmware/README.md](firmware/README.md), or [firmware-arduino/](firmware-arduino/README.md) if you prefer the Arduino IDE.
3. Install the app and set up the monitor from **Add → Set up a new monitor**.

To get an APK, build it on Expo's servers with `cloud-build.bat` (or `npx eas-cli build -p android --profile preview` in `mobile/`). Install steps are in [docs/INSTALL-APK.md](docs/INSTALL-APK.md).

## Repository layout

```text
firmware/            ESP32 firmware (PlatformIO); API.md is the device API contract
firmware-arduino/    The same firmware as an Arduino IDE sketch (generated, see its README)
mobile/              Android app
devsim/              Device emulator
hardware/            Schematic, wiring diagrams, parts lists (diagrams are generated by gen_*.py)
docs/                Architecture, physics, hardware, app and roadmap documents
scripts/             Helper scripts used by the .bat files
```

The firmware API, the emulator and `mobile/src/lib/api.ts` implement the same contract. If you change one, change the others (see [firmware/API.md](firmware/API.md)).

## Design notes

- Physics first. Machine learning only where there is real labelled data.
- Every location or loss estimate should come with a range and a confidence, not a single number.
- Detection of transients happens on the node, network-wide inference on the server.
- Nodes keep working offline and upload later.
- Indian conditions: intermittent supply, IS 10500 water quality limits, CPHEEO pressure norms, the IN865 LoRa band.
